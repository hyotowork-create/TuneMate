# DM24.8 AI 음향 튜닝 앱 구현기획서

Oct 30, 2026

## 1. 개요

TOPP PRO DM24.8을 쓰는 예배당에서 iPhone·iPad·MacBook 하나의 앱으로 음향을 측정하고, Claude가 분석하고, 믹서 값을 조정하는 앱을 만든다. 측정·분석·수동 적용(1단계)은 바로 개발할 수 있고, 믹서 자동 적용은 제어 프로토콜 역분석이 Go 판정을 받은 뒤 붙인다.

| 항목 | 내용 |
| --- | --- |
| 앱 이름 | 튠메이트(TuneMate, 가칭) |
| 대상 믹서 | TOPP PRO DM24.8 (SEIKAKU OEM 디지털 믹서) |
| 실행 기기 | iPhone, iPad, MacBook — SwiftUI 멀티플랫폼 단일 코드베이스 |
| 핵심 기능 | 음향 측정, 보정 EQ 산출, 하울링 검출·억제, Claude 대화형 진단, 믹서 자동 적용 |
| AI | Claude API (사용자 본인 API 키 연결) |
| 측정 장비 | miniDSP UMIK-1 측정마이크 (USB-C) |
| 개발 기간 | 약 10\~12주, 4단계 (Phase 0\~3) |
| 개발 방식 | 기획·설계 Claude → 구현 Codex → 리뷰 Claude (Orca·BMAD 운영) |

**목표**

1. 예배 전 리허설에서 측정부터 보정값 적용까지 한 번에 끝낸다.
2. "1번 마이크 목소리가 안 들려요" 같은 말로 원인을 진단하고 조정값을 제시받는다.
3. 하울링 주파수를 자동으로 찾아 억제한다.

**범위에서 제외**: 예배 중 사람 승인 없는 자동 조정, DM24.8 외 다른 믹서 지원(추후 검토).

## 2. 현황 분석

DM24.8은 전용 iPad 앱으로만 제어되고 공개 제어 프로토콜이 없다. 그래서 측정·분석 기능은 바로 만들 수 있지만, 믹서 자동 적용은 역분석이 전제다.

**DM24.8 제어 구조**

- 중국 SEIKAKU가 개발한 2세대 디지털 믹서를 TOPP PRO 브랜드로 판매하는 OEM 제품이다. 전용 iPad 앱이 네트워크로 믹서를 제어한다.
- 앱이 다루는 기능: 마이크 프리앰프 24채널, Aux 8개, 게이트·컴프레서·4밴드 파라메트릭 EQ, 딜레이, 씬 저장, DCA 12개. 원격 제어는 이더넷 또는 USB.
- 공식 앱은 원격 조작 전용이다. 측정이나 자동 튜닝 기능은 없다.
- 미국 App Store판 앱은 Apple Silicon Mac에서도 실행된다고 표기되어 있다. 패킷 캡처 환경을 꾸밀 때 활용할 수 있다.
- Behringer X32·Yamaha DM7처럼 OSC 사양이 공개된 믹서와 달리, DM24.8은 공개 문서를 찾을 수 없다.

**큐에어(CueAir)와 비교**

| 항목 | 큐에어 | 튠메이트(계획) |
| --- | --- | --- |
| 지원 믹서 | Behringer·Midas XR18·XR16·XR12·MR18·X18·X32·M32 | TOPP PRO DM24.8 |
| 실행 기기 | Mac (iPad판 출시 준비 중) | iPhone·iPad·MacBook |
| AI | ChatGPT·Claude 계정 연결 | Claude API |
| 하울링 억제 | RTA로 감지 후 PEQ 노치·GEQ로 자동 억제 | 같은 방식 + 측정마이크 기반 검증 |
| 공간 측정 튜닝 | 없음 | 스윕 측정 → 보정 EQ 산출 |
| 믹서 제어 방식 | 공개 OSC | 프로토콜 역분석 필요 |

**핵심 제약**

1. 제어 프로토콜 비공개 — 자동 적용(Phase 2)은 역분석 성공이 전제다.
2. 메인 출력 EQ 구성 미확인 — 공개 사양에는 채널 4밴드 PEQ만 나온다. 출력단 GEQ 유무와 밴드 수를 기기에서 확인해야 보정 알고리즘의 필터 수가 정해진다.
3. iPad 앱은 App Store 암호화가 걸려 있어 REA로 직접 분석하기 어렵다. 대신 SEIKAKU가 배포한 Mac용 유틸리티를 분석 대상으로 쓴다.

## 3. 시스템 아키텍처

앱은 측정·분석·Claude·안전 계층·믹서 드라이버·화면으로 나뉘고, 모든 믹서 변경은 안전 계층을 지난다. 믹서 드라이버가 없어도 측정부터 변경안 제시까지는 동작한다.

## 5. 모듈 1 — 측정·분석 엔진

좌석 여러 곳에서 스윕을 측정해 평균 응답을 만들고, 목표 곡선과의 차이를 믹서 EQ 밴드 수에 맞춘 컷 위주 필터로 바꾼다. 이 모듈은 믹서 제어 없이도 단독으로 동작한다.

**측정 방식**

| 방식 | 신호 | 용도 | 정확도 |
| --- | --- | --- | --- |
| 스윕 측정 | 로그 사인 스윕 | 공간·스피커 보정, 딜레이 정렬 | 높음 (임펄스 응답까지 산출) |
| 실시간 RTA | 핑크노이즈 또는 실제 음원 | 빠른 확인, 하울링 검출 | 보통 (저역 변동 큼) |

**입력 처리**

- UMIK-1 보정 파일(시리얼 번호별)을 불러와 주파수별로 보정한다.
- 오디오 세션을 측정 모드로 열어 iOS·macOS의 음성 보정 처리를 끈다.
- 테스트 신호를 믹서 USB 재생 등 비동기 경로로 낼 때는 녹음 신호와 원본 스윕의 상호상관으로 시작점을 찾는다. 크기 응답에는 영향이 없다.

**보정값 산출 로직**

1. 좌석 5\~8곳 측정 → 1/6옥타브 스무딩 → 공간 평균 응답 생성
2. 목표 곡선(평탄 + 고역 완만 하강, 설정에서 변경 가능)과의 오차 계산
3. 컷 우선: 튀는 구간만 깎고, 부스트는 소폭 한도(초기값 +3dB) 안에서만 허용
4. 깊게 꺼진 구간(방 구조로 생긴 딥)은 보정 대상에서 제외
5. 필터 수를 메인 출력 EQ 가용 밴드 수로 제한하고 오차가 가장 큰 순서로 배정
6. 적용 전 예상 응답을 겹쳐 보여 주고 → 승인 → 적용 → 재측정으로 검증

**출력 형식** — 대상 출력, 밴드 번호, 주파수(Hz), 게인(dB), Q. Phase 1에서는 이 표를 보고 아이패드 공식 앱에 직접 입력하고, Phase 2부터는 앱이 바로 적용한다.

**Claude의 역할** — 측정 결과를 받아 원인을 설명한다(스피커 문제인지 방 문제인지). 보정 우선순위를 정하고, EQ로 해결되지 않는 항목(스피커 위치·각도, 반사)은 따로 짚는다. 필터 수치 자체는 앱 코드가 계산한다.

**검증 기준** — 같은 위치·같은 마이크로 REW 측정을 병행해 앱 결과와 대조한다. 차이가 크면 Phase 1 완료로 보지 않는다.

## 6. 모듈 2 — 믹서 제어 (프로토콜 역분석)

공식 iPad 앱과 믹서 사이의 통신을 캡처해 해독하고, SEIKAKU Mac 유틸리티를 REA로 분석해 교차 검증한 뒤 Swift 제어 라이브러리(DM24Kit)로 구현한다. 통신이 암호화되어 있으면 이 모듈은 중단하고 수동 적용을 유지한다.

**역분석 절차**

1. **캡처 환경** — Xcode가 설치된 Mac에 iPad를 USB로 연결하고 `rvictl -s <UDID>`로 가상 인터페이스(rvi0)를 만든 뒤 Wireshark로 캡처한다. 대안: Apple Silicon Mac에서 DM24.8 앱을 직접 실행해 캡처, 또는 관리형 스위치 포트 미러링.
2. **통제 실험** — 한 번에 한 파라미터만, 정해진 값으로, 시각을 기록하며 조작한다. 절차는 11장 체크리스트를 따른다.
3. **해독** — 포트·전송 방식(TCP/UDP), 연결 핸드셰이크, 유지 신호(keepalive), 메시지 구조(헤더·길이·체크섬), 파라미터 주소(채널·종류), 값 인코딩(페이더 dB 곡선, 주파수 로그 스케일, Q)을 찾는다. pcap 파일을 Claude가 분석한다.
4. **REA 교차 검증** — SEIKAKU가 Mac App Store에 배포한 DM24Rack Preset Utility(Wi-Fi로 프리셋 가져오기·내보내기) 등 Mac 유틸리티를 REA로 분석한다. 연결 루틴과 프리셋 파일 구조에서 전체 파라미터 목록을 보완한다. 같은 2세대 플랫폼이라 통신부를 공유할 가능성이 있다(추정, Phase 0에서 확인).
5. **미터 스트림 확인** — 채널 레벨이 실시간으로 오는지 확인한다. "1번 마이크가 안 들려요" 진단에 필요하다.

**DM24Kit 인터페이스 (Swift 패키지)**

| 기능 | 메서드 (초안) | 비고 |
| --- | --- | --- |
| 연결 | `connect(host:)`, `disconnect()` | 자동 재연결, 유지 신호 |
| 상태 읽기 | `snapshot() -> MixerState` | 전 채널·출력 파라미터 |
| 미터 | `meters() -> AsyncStream<Levels>` | 미터 스트림이 있는 경우 |
| 채널 | `setFader`, `setMute`, `setGain`, `setPan` | dB 단위 입력, 내부에서 인코딩 |
| EQ | `setEQBand(target:band:freq:gain:q:on:)` | 채널·출력 공용 |
| 센드 | `setAuxSend(ch:aux:dB:)` | 모니터 믹스 |
| 딜레이 | `setDelay(output:ms:)` | 출력 딜레이가 있는 경우 |
| 씬 | `saveScene`, `recallScene` | 변경 전 자동 백업에 사용 |

파라미터 주소와 인코딩은 코드에 박지 않고 `dm248-protocol.yaml`로 분리한다. 펌웨어 버전별로 관리해 업데이트 시 파일만 교체한다.

**Go/No-go 기준 (Phase 0)**

- Go: 평문 바이너리이고, 같은 조작이 같은 패킷을 재현하며, 패킷을 재전송하면 믹서가 같은 동작을 한다.
- No-go: 암호화·세션 인증이 있거나 재전송이 거부된다. 이때는 Phase 1(측정·분석·수동 적용)까지만 진행한다.

## 7. 모듈 3 — Claude 연동

앱 안에서 Claude API의 도구 사용(tool use)으로 대화형 진단과 조정을 처리한다. Claude는 의도와 해석을 맡고, 수치 계산과 한도 검사는 앱 코드가 맡는다. Mac에서는 같은 도구를 MCP 서버로도 열어 Claude Desktop·Claude Code에서 쓸 수 있게 한다.

**도구 명세**

| 도구 | 설명 | 믹서 변경 | 승인 |
| --- | --- | --- | --- |
| `get_mixer_state` | 전체 채널·출력 상태 요약 | 없음 | 불필요 |
| `get_channel` | 한 채널의 게인·EQ·다이내믹스·센드 | 없음 | 불필요 |
| `get_meters` | 채널별 현재 레벨 | 없음 | 불필요 |
| `get_measurement` | 최근 측정 결과와 보정 제안 | 없음 | 불필요 |
| `propose_changes` | 변경안 목록 생성 (적용 안 함) | 없음 | 불필요 |
| `apply_changes` | 승인된 변경안 적용 | 있음 | 필요 (리허설 자동 모드는 한도 내 생략) |
| `adjust_fader` · `adjust_send` | 상대값(±dB)으로 조정 | 있음 | 필요 |
| `set_eq_band` | EQ 밴드 설정 | 있음 | 필요 |
| `backup_scene` · `restore_scene` | 스냅샷 저장·복원 | 있음 | 복원만 필요 |

**안전장치**

- 한 번에 올릴 수 있는 폭(초기값 +3dB), 메인 출력 상한, 한 번에 뮤트할 수 있는 채널 수를 설정으로 제한한다.
- 팬텀 전원, 씬 불러오기, 출력 라우팅 변경은 항상 사람 확인을 거친다.
- 모든 변경 직전에 자동 스냅샷을 남기고, 변경 로그와 원클릭 되돌리기를 제공한다.
- Claude는 절대값 대신 상대값(±dB)만 넘기고, 현재값 읽기·계산·쓰기는 앱이 한 번에 처리한다.

**운영 모드**

| 모드 | 동작 | 사용 시점 |
| --- | --- | --- |
| 제안 모드 (기본) | Claude가 변경안을 보여 주고 사람이 적용 버튼을 누른다 | 평상시 |
| 리허설 자동 모드 | 한도 안의 변경은 바로 적용, 한도 밖은 승인 요청 | 예배 전 리허설 |
| 예배 잠금 모드 | 읽기 전용, 진단과 제안만 | 예배 중 |

**대화 맥락 구성** — 채널 이름표(예: 1=설교, 5·6=찬양 보컬), 공간 정보(좌석 수, 스피커 구성), 최근 측정 결과, 현재 모드를 매 요청에 함께 보낸다.

**모델·키** — 일상 대화와 조정은 Sonnet급 모델, 측정 결과 정밀 분석은 Opus급 모델을 쓴다(구현 시점에 모델명 확인). API 키는 사용자 본인 것을 Keychain에 저장한다. 인터넷이 끊겨도 측정·수동 적용 기능은 동작한다.

**사용 예** — "1·5·6번 보컬에 리버브 조금 넣어줘" → 채널·FX 상태 읽기 → 센드 변경안 3건 제시(현재값 → 제안값) → 적용 → 변경 로그 기록. 큐에어 화면에서 확인한 흐름과 같다.

## 8. 모듈 4 — 자동 튜닝·하울링 억제 루프

측정 → 계산 → 적용 → 재측정을 목표에 들 때까지 반복하는 두 개의 루프다. 믹서 드라이버(Phase 2)가 있어야 자동으로 돌고, 없으면 적용 단계만 사람이 아이패드로 한다.

&#91;embedded content: 자동 튜닝·하울링 억제 루프 · 두 갈래, 각 1개 판정\]

공간 튜닝은 사람 승인 뒤에만 적용되고, 하울링 억제는 리허설 자동 모드에서 한도 안의 노치만 바로 적용한다.

**설계 초기값 (현장 테스트로 조정)**

| 항목 | 초기값 | 메모 |
| --- | --- | --- |
| 하울링 후보 판정 | 주변 대역보다 뚜렷하게 솟은 좁은 피크가 일정 시간 지속하며 커짐 | 음악·목소리의 일시적 피크와 구분 |
| 노치 깊이 | 한 번에 −3dB, 최대 −12dB | 한도에 닿으면 게인을 낮추도록 안내 |
| 노치 폭 | 좁게 (높은 Q) | 주변 음색 손실 최소화 |
| 노치 위치 | 해당 채널의 빈 PEQ 밴드 → 없으면 메인 출력 EQ | DM24.8 채널 PEQ는 4밴드 |
| 공간 튜닝 반복 | 최대 3회 | 수렴하지 않으면 원인(위치·반사)을 Claude가 설명 |

**링아웃 모드** — 리허설 전에 보컬 마이크 게인을 천천히 올려 하울링이 먼저 나는 주파수를 찾고 미리 노치를 걸어 둔다. 이 작업은 내장 마이크로도 충분하다.

## 10. 리스크와 법적 검토

가장 큰 리스크는 통신 암호화로 자동 적용이 막히는 경우다. 이때도 측정·분석·수동 적용 앱은 그대로 쓸 수 있어 투자가 버려지지 않는다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 통신 암호화·세션 인증 | 자동 적용 불가 | Phase 0에서 판정, No-go면 Phase 1까지만 진행 |
| 믹서 펌웨어 업데이트 | 해독한 규칙이 깨짐 | 완성 후 펌웨어 고정, 앱이 버전 확인 후 불일치 시 쓰기 차단 |
| 잘못된 패킷 전송 | 믹서 오작동 | 테스트 씬에서만 개발, 예배 잠금 모드, 변경 전 자동 스냅샷 |
| 공식 iPad 앱과 동시 접속 충돌 | 값 덮어쓰기, 연결 끊김 | Phase 0에서 동시 접속 허용 여부 확인 |
| 내장 마이크 측정 오차 | 잘못된 보정 | 공간 보정은 UMIK-1 필수, 내장 마이크는 하울링 검출 보조만 |
| EQ 과보정 | 소리가 부자연스러워짐 | 컷 우선, 부스트 한도, 다지점 평균, 재측정 검증 |
| Claude 분석 중단 | 바이너리 분석 지연 | 역분석 중 안전장치로 응답이 멈추는 사례가 보고됨 → 패킷 분석 중심으로 진행 |
| 인터넷·API 장애 | AI 기능 정지 | 측정·수동 적용은 오프라인 동작 |
| 앱 배포 | 비공식 제어 앱 심사 불확실 | 교회 내부 TestFlight 배포 우선, 공개 출시는 별도 검토 |

**법적 검토 (일반 정보, 법률 자문 아님)**

- 저작권법 제101조의4는 정당하게 프로그램을 쓰는 사람이 호환에 필요한 정보를 다른 방법으로 얻기 어려울 때, 필요한 부분에 한해 허락 없이 역분석하는 것을 허용한다.
- 얻은 정보를 호환 외 목적으로 쓰거나, 원래 프로그램과 실질적으로 비슷한 프로그램을 만드는 데 쓰는 것은 금지된다.
- 본 계획은 교회가 소유한 믹서를 제어하는 호환 도구이고, 공식 앱을 복제하지 않으므로 허용 범위에 들어갈 가능성이 높다.
- 디컴파일 코드는 저장소에 넣지 않고, 해독한 프로토콜 명세만 보관한다.
- 공개 배포·판매·타 교회 제공으로 확대할 때는 변호사 검토를 받는다. 앱에는 "TOPP PRO·SEIKAKU와 무관한 독립 앱" 문구를 표시한다.

## 11. 현장 운영 가이드

Phase 0 캡처는 믹서 앞에서 15분 정도면 끝난다. 아래 순서대로 진행하고, 캡처 파일과 기록표를 Claude에게 넘기면 해독을 시작한다.

**A. Phase 0 패킷 캡처 체크리스트**

준비물: MacBook(Xcode·Wireshark 설치), iPad(DM24.8 앱), USB-C 케이블, 아래 기록표

- [ ] 믹서 현재 씬을 새 번호로 백업
- [ ] iPad를 MacBook에 USB로 연결하고 "이 컴퓨터 신뢰" 승인
- [ ] 터미널에서 `rvictl -s <iPad UDID>` 실행 → rvi0 생성 확인
- [ ] Wireshark에서 rvi0 캡처 시작
- [ ] DM24.8 앱 실행 후 믹서 연결 (연결 과정 기록)
- [ ] 30초 동안 아무것도 조작하지 않기 (유지 신호 확인)
- [ ] CH1 페이더: 최소 → −20 → −10 → 0 → +10dB, 단계마다 5초 대기
- [ ] CH1 뮤트 켜기 → 끄기
- [ ] CH1 EQ 1밴드: 주파수만 → 게인만 → Q만 각각 변경
- [ ] CH1 → Aux1 센드 변경
- [ ] 메인 페이더 변경
- [ ] 다른 씬 불러오기 → 원래 씬 복원
- [ ] 캡처 저장(.pcapng) → 기록표와 함께 전달
- [ ] `rvictl -x <iPad UDID>`로 정리

| 시각 | 조작 | 설정값 |
| --- | --- | --- |
| 예: 14:02:10 | CH1 페이더 | −20dB |
|  |  |  |
|  |  |  |

**B. 공간 측정 체크리스트**

- [ ] UMIK-1 보정 파일을 앱에 등록 (시리얼 번호로 다운로드)
- [ ] 측정용 빈 채널에 테스트 신호 연결, 채널 EQ·다이내믹스 끄기
- [ ] 메인 출력 EQ를 평탄(0dB)으로 초기화한 상태를 씬으로 저장
- [ ] 평소 예배 음량에 가깝게 레벨 설정 (장시간 큰 음량 노출 주의)
- [ ] 마이크를 앉은 귀 높이에 두고 좌석 5\~8곳 측정
- [ ] 보정 제안 확인 → 적용 → 같은 위치에서 재측정
- [ ] 결과 씬을 새 번호로 저장

**C. 예배 운영 규칙**

1. 예배 중에는 예배 잠금 모드만 쓴다. 변경은 음향 담당자가 공식 앱이나 실물 페이더로 한다.
2. 측정과 자동 조정은 리허설 시간에만, 예배 시작 30분 전까지 끝낸다.
3. 모든 변경은 스냅샷이 남은 상태에서만 한다.
4. 이상 동작 시 즉시 앱 연결을 끊고 백업 씬을 불러온다.
